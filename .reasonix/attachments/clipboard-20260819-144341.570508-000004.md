# V0.4B：真实医院化验单识别

当前 Flutter 健康档案项目已经完成：

- V0.2 UI 框架
- V0.3 Drift 本地健康数据库
- 手工录入
- 日常健康记录
- 历史数据
- 编辑 / 删除
- V0.4A 报告图片上传
- 图片预览
- Mock 报告识别
- 识别结果确认
- 报告与健康指标关联
- 原始报告保存

现在进入 V0.4B。

---

# 一、本版本核心目标

把目前：

真实图片
→ Mock 假识别结果

升级为：

真实医院报告图片
→ 真实 OCR / 图像识别
→ AI 结构化
→ 标准指标匹配
→ 用户确认
→ Drift 入库

最终目标：

用户拿一张真实的血常规、生化、肝功能、肾功能、血脂或血糖报告，通过拍照或者上传图片，可以自动提取其中的检查数据。

---

# 二、本版本最重要原则

这一版不要做任何疾病诊断。

AI 的任务只有：

**“读取和整理报告中已经存在的信息。”**

允许：

- 识别指标名称
- 识别结果
- 识别单位
- 识别参考范围
- 识别异常标记
- 识别医院
- 识别报告日期
- 将指标映射到内部标准指标
- 计算是否超过用户报告中给出的参考范围

禁止：

- 判断用户患有什么疾病
- 预测疾病
- 推荐药物
- 推荐停药
- 修改药物剂量
- 自动生成医疗治疗方案
- 根据单次化验结果下诊断结论

# 七、API Key 安全

非常重要：

**任何真实 OCR / AI API Key 禁止直接写进 Flutter App。**

因为 App 安装包可以被反编译。

正确结构：

Flutter App
↓
自己的后端接口
↓
OCR / AI 服务
↓
自己的后端
↓
Flutter

即：

手机不能直接保存第三方模型 API Secret。

# 十、OCR 层负责什么

OCR 只负责尽可能读取报告内容，例如：

深圳XX医院

检验日期：2026-08-18

项目            结果        单位         参考范围

谷丙转氨酶       32          U/L          9-50

尿酸             480         μmol/L       210-420

肌酐             93          μmol/L       57-111

糖化血红蛋白     6.8         %            4.0-6.0

---

OCR 不负责医学判断。

---

# 十一、AI 层负责结构化

AI 接收到 OCR 文字后，只把它转换成结构化 JSON。

例如：

```json
{
  "hospitalName": "深圳XX医院",
  "reportDate": "2026-08-18",
  "reportType": "生化检查",
  "metrics": [
    {
      "rawName": "尿酸",
      "value": 480,
      "unit": "μmol/L",
      "referenceMin": 210,
      "referenceMax": 420,
      "referenceText": "210-420"
    }
  ]
}
```

---

# 十二、AI 输出必须严格 JSON

不要让模型返回解释性文章。

不要返回 Markdown。

不要返回：

“根据您的检查报告……”

只允许返回定义好的 JSON Schema。

如果返回内容无法解析：

识别任务失败

→ 提示用户重新识别。

不要把无法解析的数据强行写数据库。

---

# 十三、报告基本信息

尽量识别：

- hospitalName
- reportDate
- reportType
- patientName

其中 patientName：

仅用于用户核对。

目前不要以患者姓名作为数据库身份判断条件。

用户账号才是数据归属依据。

---

# 十四、指标字段

每一项至少提取：

- rawName
- value
- unit
- referenceMin
- referenceMax
- referenceText
- originalStatus
- confidence

例如：

rawName:
尿酸

value:
480

unit:
μmol/L

referenceMin:
210

referenceMax:
420

originalStatus:
H

---

# 十五、不要完全相信 AI 的状态

最终：

偏高 / 偏低 / 正常

应优先根据：

value

+

报告本身 referenceMin/referenceMax

由本地程序计算。

例如：

value > referenceMax

→ 偏高

value < referenceMin

→ 偏低

否则：

→ 正常

如果参考范围缺失：

→ 未判断

AI 不得自行创造参考范围。

---

# 十六、非常重要：禁止 AI 补全不存在的数据

如果报告里没有：

参考范围

就返回：

null

不要根据模型医学知识自动填参考范围。

如果报告里没有：

单位

返回 null。

如果报告日期看不清：

返回 null。

原则：

**看不到就承认看不到。**

绝对不要为了 JSON 完整而猜。
