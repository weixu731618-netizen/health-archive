当前 Flutter 项目 V0.3 已经完成：

- 手工录入健康指标
- 日常健康记录
- Drift 本地数据库
- 历史记录
- 编辑/删除
- 身体系统页面读取真实数据

现在进入 V0.4。

本阶段目标：

让用户上传一张医院化验单图片，系统自动识别其中的检查指标，经过用户确认后批量写入现有 Drift 健康数据库。

---

# 一、本版本核心闭环

必须实现：

选择化验单图片  
→ OCR/AI 识别  
→ 得到结构化指标  
→ 用户逐项检查和修改  
→ 点击确认  
→ 批量写入 Drift  
→ 自动出现在“记录”和对应身体系统中

第一版只针对：

- 血常规
- 生化检查
- 肝功能
- 肾功能
- 血脂
- 血糖
- 尿常规等结构化检验报告

暂时不要处理：

- CT
- MRI
- 胃镜
- 肠镜
- 心电图图像
- 病理
- 超声复杂文字结论
- 医生病历
- 处方

---

# 二、开发原则

我不会编程，请遵守：

1. 不要重构已经稳定的 V0.3。
2. 新功能尽量独立封装。
3. 不删除现有手工录入能力。
4. OCR/AI 失败时，用户仍然可以手工录入。
5. AI 识别结果不能直接写入正式数据库。
6. 必须经过用户确认。
7. 原始图片必须保留。
8. 不做疾病诊断。
9. 不做用药建议。
10. 不做风险预测。
11. 不做云同步。
12. 不做手机号登录。
13. 不做家庭共享。

---

- 拍摄检查报告

本阶段优先实现：

“上传报告”

# 五、识别架构

不要把 OCR 或大模型 API Key 直接写在 Flutter 客户端代码中。

请设计一个独立接口层，例如：

ReportRecognitionService

当前阶段允许先实现：

MockReportRecognitionService

用于跑通完整产品流程。

同时预留：

RemoteReportRecognitionService

未来连接真实 OCR / AI 服务。

App 页面不要直接依赖具体 AI 提供商。

结构：

ReportImportPage  
↓  
ReportRecognitionService  
↓  
返回 StructuredMedicalReport  
↓  
ReportReviewPage  
↓  
用户确认  
↓  
Drift

---

# 六、结构化报告模型

建立：

StructuredMedicalReport

至少包含：

- hospitalName
- reportDate
- reportType
- patientName
- metrics
- rawText
- sourceImagePath

其中：

metrics 为 List<RecognizedMetric>

---

# 七、单个识别指标模型

- canonicalName
- value
- unit
- referenceMin
- referenceMax
- referenceText
- status
- bodySystem
- confidence
- isSelected
- notes

0.96

isSelected:
true

# 十、低置信度提示

如果 confidence < 0.8：

显示：

“请重点核对”

不要自动删除。

例如：

⚠ 识别可信度较低，请核对原报告

# 十一、编辑识别结果

用户点击某一指标：

进入编辑状态或弹窗。

允许修改：

- 指标名称
- 数值
- 单位
- 参考下限
- 参考上限
- 检查日期
- 身体系统

如果 matchedMetricId 未识别：

显示：

“未匹配标准指标”

允许用户从现有 metric_dictionary 中选择正确指标。

# 十二、标准指标匹配

复用 V0.3 已有的健康指标字典。

例如 OCR 得到：

血清肌酐

应尽量映射到：

CREA

canonicalName:

肌酐

OCR 得到：

Cr

也尽量映射 CREA。

---

第一版先支持精确别名匹配。

不要做复杂 NLP。

建立 aliases，例如：

CREA:

- 肌酐
- 血清肌酐
- Cr
- Creatinine

HBA1C:

- HbA1c
- 糖化血红蛋白
- 糖化血红蛋白A1c
- GHb

UA:

- 尿酸
- 血尿酸
- UA
- Uric Acid

# 十六、原始报告必须保留

这是医疗数据的重要原则。

结构化数据不能替代原始报告。

用户以后必须可以查看：

原报告图片

因此每份报告同时保存：

原始文件

+

结构化指标

---

# 十七、删除逻辑

删除一份报告时：

必须弹出二次确认：

“删除报告后，与该报告关联的检查指标也将删除。是否继续？”

不要默认静默删除。

如果用户只删除某一条指标：

不要自动删除整份报告。

---

---

# 十九、隐私设计

虽然现在只是本地 MVP，但代码结构要考虑以后医疗数据隐私。

要求：

1. 不在日志中打印完整健康数据。
2. 不在日志中打印原始报告全文。
3. 不把 API Key 写进 Flutter 客户端。
4. 不把患者姓名等信息发送给不必要的模块。
5. 识别 Service 与 UI 解耦。
